# Unity 远程监控网站部署配置教程

## 准备内容

需要：

- 一个 Supabase 免费账户
- 一个 Vercel Hobby 账户
- Node.js 和 pnpm
- Vercel 后端源码目录
- UnityRemoteMonitor Package

不要把任何 Token、Secret Key、device-api-key.txt 或环境变量文件上传到公开 GitHub。

## 第一步：创建 Supabase 项目

1. 打开 https://supabase.com/dashboard
2. 点击 New project。
3. Project name 可填写 unity-device-monitor。
4. 自己设置并保存数据库密码。
5. Region 选择距离设备较近的区域。
6. 选择 Free 并创建项目。

## 第二步：创建数据表

1. 进入 Supabase 项目的 SQL Editor。
2. 点击 New query。
3. 打开本目录的 supabase.sql。
4. 复制全部 SQL 并粘贴。
5. 点击 Run。
6. 出现 Success. No rows returned 即成功。

## 第三步：取得 Supabase 参数

在 Project Settings 的 Data API 页面复制 API URL。

正确格式：

    https://xxxxxxxx.supabase.co

不要复制末尾的 /rest/v1/，也不要复制 PostgreSQL 连接字符串。

在 Project Settings 的 API Keys 页面复制 Secret key 或旧版 service_role key。不要使用 publishable 或 anon key。Secret key 只能配置在 Vercel，不能放进 Unity。

## 第四步：创建 Vercel Token

1. 打开 https://vercel.com/account/tokens
2. Token name 填写 unity-device-monitor-cli。
3. Scope 选择自己的账户。
4. Expiration 可选择 30 天。
5. 点击 Create 并保存以 vcp_ 开头的 Token。

## 第五步：准备 Node.js 和 pnpm

普通电脑建议安装 Node.js LTS，然后执行：

    npm install -g pnpm

检查：

    node --version
    pnpm --version

两个命令都显示版本号后再继续。

## 第六步：运行半自动配置向导

右键 PowerShell，以普通用户身份打开，执行：

    Set-ExecutionPolicy -Scope Process Bypass
    & "D:\Unity project\UnityRemoteMonitor-Deployment\Setup-UnityMonitor.ps1"

脚本会询问：

1. Vercel Token
2. Supabase API URL
3. Supabase Secret Key

随后自动：

- 连接 Vercel 项目
- 添加 SUPABASE_URL
- 添加 SUPABASE_SERVICE_ROLE_KEY
- 生成并添加 DEVICE_API_KEY
- 生成并添加 CONTROL_API_KEY
- 进行 Production 部署

密钥输入使用安全输入，不会在输入时显示。脚本结束时会显示新生成的 DEVICE_API_KEY 和 CONTROL_API_KEY，请立即保存。

如果后端目录不同：

    & ".\Setup-UnityMonitor.ps1" -ProjectDirectory "你的后端目录" -VercelProjectName "你的项目名"

如需直接生成 device-api-key.txt：

    & ".\Setup-UnityMonitor.ps1" -DeviceKeyOutputDirectory "D:\你的Unity打包目录"

## 第七步：检查部署

访问：

    https://你的Vercel项目名.vercel.app/api/status

正常返回：

    {"devices":[]}

再访问网站首页，应看到 Unity 设备监控页面。

## 第八步：Unity 接入

1. 导入 UnityRemoteMonitor unitypackage。
2. 将 Remote Device Monitor 预制体拖入启动场景。
3. 填写唯一的 Project Id 和易读的 Project Name。
4. 保持服务器地址为自己的 Vercel 地址。
5. 将 device-api-key.txt 放在项目根目录进行编辑器测试。
6. 打包后把同一文件放到 exe 旁边。
7. 启动后等待约 30 秒并刷新网站。

## 第九步：网页控制

首次点击播放按钮时，网页会要求 CONTROL_API_KEY。输入脚本生成的 CONTROL_API_KEY。它只保存在当前浏览器标签页的 sessionStorage 中，关闭标签页后需要重新输入。

Unity 预制体的 On Video Command 要绑定到作品自己的 public 方法，并选择 Dynamic int。

## 常见错误

数据库尚未配置：检查 Vercel Production 是否有三个 Supabase/设备环境变量，并重新部署。

设备密钥错误：device-api-key.txt 与 Vercel 的 DEVICE_API_KEY 不一致。

控制密钥错误：浏览器输入的值与 CONTROL_API_KEY 不一致；关闭标签页或清除 sessionStorage 后重试。

404：确认 api/status.js 和 api/command.js 已部署。

设备离线：确认程序在运行、能联网、预制体已加载，且密钥文件位于正确目录。

fetch failed：Node.js 没有使用代理或网络无法访问平台 API。配置 HTTP_PROXY、HTTPS_PROXY 和 NODE_USE_ENV_PROXY，或使用允许 Node.js 联网的网络。

## 安全和维护

- Supabase Secret Key 和 Vercel Token 永远不能进入 Unity。
- DEVICE_API_KEY 泄露后，在 Vercel 中替换并重新部署，同时替换所有设备文件。
- CONTROL_API_KEY 泄露后，在 Vercel 中替换并重新部署。
- 公开仓库使用示例服务器地址，不要公开个人部署地址和真实状态接口。
- Vercel Hobby 适用于个人 Demo；正式商业使用前检查服务条款与额度。

## 免费额度估算

30 秒上报一次时，每台设备每月约 86400 次调用。少量设备适合 Demo；设备增多时可改成 60 至 90 秒上报一次，并降低网页刷新频率。
